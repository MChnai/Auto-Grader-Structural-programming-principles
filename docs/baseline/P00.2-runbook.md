# P00.2 — Reproducing the original functional audit

## Scope

This stage **audits and classifies** the original implementation without changing production algorithms. Tests cover ZipExtractor, CompilerEngine, NativeProcessExecutor, CppCodeAnalyzer, SubmissionGrader, OutputChecker, WinnowingEngine, and AutoGraderCommand.

The baseline Java source remains unchanged in this feature branch. `scripts/p00_2/P002Probe.java` contains synthetic fixtures. `scripts/p00_2/run_audit.py` compiles the live source and runs each fixture in a separate process with an external timeout, writing machine-readable JSON and Markdown reports.

## Prerequisites

- Java 21 JDK with `javac` and `java`
- Python 3.10+
- `g++` in `PATH`
- A working Maven installation to independently test the full project
- A local disposable test environment: the original code executes the generated C++ binaries natively; **never give these probes untrusted submissions**

## Windows PowerShell

```powershell
# On a clean feature branch (do not merge into main)
git status --short
java -version
mvn -version
g++ --version

mvn clean verify
mvn -DskipTests package

python scripts/p00_2/run_audit.py `
  --runtime-jar target/autograder-1.0.0-cli.jar `
  --output-dir p00-2-results
```

The runner does **not** use Maven to compile source: it recompiles `src/main/java` with `javac`, using the shaded CLI JAR for external dependencies only, so every probe executes the current source version. Review `p00-2-results/P00.2-results.json` and `p00-2-results/P00.2-functional-audit.md`.

For `compile_timeout` and `compile_stderr_flood`, the audit runner now builds a temporary fake `g++` executable for the current OS; native Windows no longer requires a shell wrapper. These checks must be run and validated on your Windows machine (this patch was verified locally on Linux only). `--skip-slow` intentionally marks `compile_timeout` BLOCKED.

Run a smaller selection with repeated `--case NAME` arguments. This is useful when verifying the Windows-specific line-ending fix and the two distinct large-stdin behaviors.

## Classifying results

- **PASS**: observed behavior satisfies the explicit test assertion; not a general proof of correctness.
- **FAIL**: assertion mismatched or watchdog detected a stalled process. This is a baseline finding, not a failed remediation.
- **OBSERVED**: quantitative/contract-dependent behavior recorded without a universal pass/fail label.
- **BLOCKED**: environment constraint prevented executing the case; never count as PASS.

Do not change production classes to make P00.2 green. Implement fixes later, especially P02 (sandbox/process), P04 (AST), P07 (similarity benchmark), P09 (rubric), P10 (CLI), and compare to these results.

## Git workflow

1. `git switch main` / `git pull --ff-only origin main` on your real repository.
2. Create `feature/AX-P00-functional-audit` from your P00.1 feature head (or from main after P00.1 is merged via GitHub PR).
3. Apply `autograder-x-P00.2.patch` or copy only `scripts/p00_2/` and `docs/baseline/P00.2*`.
4. Run tests, commit `[AX-P00] Audit original functional behavior`, push feature branch, and open a PR against the selected GitHub base.
5. Do not merge locally in VS Code. The supplied patch does not merge or change `main`.
