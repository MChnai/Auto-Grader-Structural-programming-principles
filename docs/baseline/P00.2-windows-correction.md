# P00.2 — Windows audit corrections (audit-only)

## Evidence from the first user Windows run

The first run reported 29 PASS, 13 FAIL, 2 OBSERVED, 2 BLOCKED (46 scenarios). The `native_normal` failure prints `30`, but the original assertion required the exact LF representation `"30\n"`. Windows C++ binaries can produce CRLF. The first run did **not** print the character codes, so that failure is **likely**, not definitively, a line-ending false positive.

The `native_input_big` fixture originally sent 2 million bytes to a C++ program that never read stdin. `The pipe has been ended` is consistent with a child exiting early, not proof that large input cannot be delivered to a consumer.

The compiler timeout checks were BLOCKED on Windows because the first audit used Unix shell wrappers. No compiler timeout verdict can be inferred from those two BLOCKED cases.

## Changes in the corrected audit

1. Accept CRLF or LF only for `native_normal`, and print escaped newlines on mismatches.
2. Make `native_input_big` read and count all bytes. A separate `native_input_early_exit` case tests whether the executor handles early child exit without losing stdout and exit information.
3. Simulate compiler delays with a temporary C++ executable compiled using the real `g++`, avoiding the Linux-only shell wrapper.
4. Add `--case` for targeted reruns. The full audit now defines **47** scenarios (one additional stdin early-exit case).
5. Keep `src/main/java/**` and `pom.xml` unchanged. These changes do **not** fix baseline bugs.

## Local verification scope

The corrected `P002Probe.java` was compiled locally. Its selected Linux fixtures produced:

- `native_normal`: PASS
- `native_input_big`: PASS with stdout `2000000`
- `native_input_early_exit`: FAIL with a process I/O error, confirming that the separate early-exit behavior is still a baseline issue.

Two additional Linux checks were executed against the new native fake-compiler simulator: `compile_stderr_flood` FAIL (watchdog after 8 seconds); `compile_timeout` FAIL (compiler returned success after an artificial 32-second delay without reporting the 30-second timeout). These results verify the simulator on Linux. **Native Windows compiler-wrapper behavior remains unverified** until you rerun on Windows. Previous published baseline report files should remain intact and identifiable rather than being silently overwritten.
